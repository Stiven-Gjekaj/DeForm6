<objective>
Give DeForm6 a mode. Strict refuses a file whose read had to assume a value,
and names the byte offset. Salvage produces the output and writes every
assumption into the report.

Purpose: `Journal` and `Mode` have sat in `crates/deform6/src/journal.rs` since
Phase 1 with a full test suite and no caller. A grep for the word `Journal`
outside its own file returns nothing. The crate therefore has one behaviour
today, and it is the salvage behaviour: it continues past every recoverable
defect, always, with no way to ask it not to.

The measurement that shapes this plan: 36 of the 44 vendored corpus programs
raise at least one defect today, 430 defects in all. A mode that refuses on
any `Recoverable` defect would refuse 36 undamaged programs and destroy the
Phase 2, 3 and 4 gates. The two kinds those 430 defects carry cost one item
each and assume nothing in its place. A third severity is what tells them
apart from a defect the reader continued past by inventing a value.

Output: a three value severity ladder, a three way policy in `Journal::record`,
a mode parameter on the two public entry points, `--salvage` on both
subcommands, and an assumption list in the JSON report.
</objective>

<assumption_delta_decision>
**Noun that is now primary:** `Severity`, not `Mode`.

**Decision: add-alongside.** `Mode` joins the read as a disposition applied to
the finished read. It does not enter the read itself. No parse site branches on
it, and a source assertion in task 2 proves that no file under
`crates/deform6/src/vb/` or `crates/deform6/src/read/` names `Mode` at all.
The identity of the read does not move from "the read" to "the read under a
mode", because the bytes the reader touches are the same in both modes. Only
the disposition of the finished result differs.

**Rationale:** roadmap success criterion 3 states that the defect list is the
same in both modes. A design that branches inside the read cannot deliver that,
because a strict run that refuses at the first recoverable defect collects a
prefix of the list a salvage run collects. A disposition applied after the read
delivers it exactly, and `Journal::record` pushes the defect before it applies
the policy, which is the property the journal was built with.

**What forces a promote later:** a defect kind whose salvage recovery needs a
different parse continuation, for example a re-scan that starts from a
different offset, or a second pass that reads bytes a strict run never touches.
On the day one such kind exists, the mode must enter the read, every read
function must take it, and this decision becomes `promote`.

**The second signal, `-runs=N` against `-max_total_time`, is decided in plan
05-03**, which owns the command that encodes the flag. The remaining two
signals, `also` and `alternative`, are `no-change`: both are ordinary prose in
the roadmap's own named risks and neither names a noun that this phase makes
plural.
</assumption_delta_decision>
