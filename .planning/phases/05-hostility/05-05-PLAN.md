<objective>
Turn a crash the fuzzer finds into a test that runs on the pinned stable
toolchain, forever, and write down the procedure that gets it there.

Purpose: `AGENTS.md` states that a crash the fuzzer finds becomes a test case
in the repository. A crash that only reproduces under nightly with a sanitizer
attached is not a test case a person can run. The replay must work in the same
`cargo test --workspace` every other test in this repository runs in.

The trap the research names, and this plan closes in its own first commit:
success criterion 2 requires that emptying the directory makes the test fail.
The harness is built before the fuzzer has found anything, so the directory is
empty at that commit and the count assertion would fail on the commit that
introduces it. The seed has to arrive in the same commit.

The second trap, which the research does not name: a seed cannot be a
truncated or patched copy of a corpus program. Every corpus program is third
party work, and `AGENTS.md` bars a fixture calculated from such a file. The
seed is therefore built from scratch by this repository's own code, and a test
proves that the committed bytes are what that code produces.

Output: a hostile image builder this repository owns, the first seed, the
stable replay with its count assertion, and the procedure written where the
next person will look for it.
</objective>
