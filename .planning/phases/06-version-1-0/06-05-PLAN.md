<objective>
Audit the dependency licences into `LICENSES.md` by re-deriving them from
`cargo metadata`, and write the changelog.

Purpose: the roadmap names "the licence check" as a release deliverable. Decision
D-03 settles how: a manual audit into `LICENSES.md`, with no `cargo-deny` and no
`deny.toml`. Decision D-03 also settles the acceptance check: the list is
re-derived from `cargo metadata`, so the file is measured rather than asserted.
`06-PATTERNS.md` found `corpus/NOTICES` is an exact analog for the file's shape.
`06-RESEARCH.md` found no `CHANGELOG.md` and no format precedent in this
repository, so a plain reverse-chronological Markdown list is the default this
plan picks and says so.

Output: `cargo run -p xtask -- licences`, `LICENSES.md` and `CHANGELOG.md`.
</objective>

    Create `crates/xtask/src/licences.rs`. Open it with a module doc comment
    stating what the subcommand does, why the audit is manual rather than a
    `cargo-deny` run, and that the file it renders is checked by re-rendering it
    rather than by reading it.

    Give it a `pub fn run() -> i32` in the shape `update_ratios` uses: an inner
    function returning `Result<_, String>`, and a wrapper that prints the result or
    prints the error to stderr and returns a non-zero code.

    The inner function:
    - Runs `cargo metadata --format-version 1 --all-features --locked` with
      `std::process::Command`, building the argument vector one argument at a time.
      Never build a shell string.
    - Parses the JSON output with `serde_json`.
    - Takes the `packages` array. For each package read `name`, `version`,
      `license` and `repository`.
    - Excludes the three workspace members by name: `deform6`, `deform6-cli` and
      `xtask`. This is what makes the rendered file independent of the workspace
      version, so plan 06-04's bump to 1.0.0 can never invalidate it.
    - Writes the licence cell as the string `cargo metadata` returned. When the
      `license` field is absent, write the literal `not stated` and nothing else.
      A package with no stated licence is recorded as having none stated. Do not
      look one up, and do not guess.
    - Sorts by package name, then by version, so the rendering is deterministic and
      a diff of two runs is meaningful.
    - Renders a Markdown document in the shape of `corpus/NOTICES`: a lead
      paragraph naming what the file is, the exact command it was built from, and
      the date; then a table with the columns `Crate`, `Version`, `Licence`,
      `Source`; then a closing section listing each distinct licence expression
      once with the count of packages that carry it.
    - Refuses to write a file holding fewer than 20 rows, the same way
      `update_ratios` refuses to write fewer than its minimum program count. A
      rendering that suddenly holds three rows is a broken `cargo metadata` call,
      not a smaller dependency tree.
    - Writes the result to `LICENSES.md` at the repository root.

    Wire it into `crates/xtask/src/main.rs`: add the `mod licences;` declaration
    beside the existing module declarations, add `Some("licences") => licences::run(),`
    to the `match`, and add `licences` to the `USAGE` string.

    Run `cargo run -p xtask -- licences` once and commit the `LICENSES.md` it
    produced.

    numbers move once the `jsonschema` dev-dependency is in the tree. Do not write
    either number into the code or into the plan summary as a target. The file is
    rendered, and the check is that re-rendering it changes nothing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cargo metadata` output -> the rendered licence file | Subprocess output is parsed as JSON and rendered into a committed document |
| the dependency tree -> the release | 78 or more third party packages ship inside the built binary's provenance |
| the changelog -> the reader | A release note is a claim surface like any other |

## STRIDE Threat Register

ASVS level 1. Blocking severity: high.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05-01 | Tampering | the `cargo metadata` subprocess | high | mitigate | The argument vector is built one argument at a time with `std::process::Command`, never as a shell string, matching the idiom `crates/xtask/src/fuzz.rs` already documents. No caller-supplied byte reaches a shell. |
| T-06-05-02 | Repudiation | `LICENSES.md` content | high | mitigate | Every cell is the string `cargo metadata` returned. An absent licence is rendered as `not stated`, never as a guess. The acceptance check is a re-derivation, so a hand edit to the file fails the gate. |
| T-06-05-03 | Denial of Service | a truncated or empty `cargo metadata` result | medium | mitigate | The renderer refuses to write fewer than 20 rows, matching how `update_ratios` refuses to write fewer than its minimum program count. A rendering that collapses is a broken call, not a smaller tree. |
| T-06-05-04 | Repudiation | `CHANGELOG.md` authorship | medium | mitigate | A counted check rejects a co-author line, a tool name or a session link. `AGENTS.md` states the reason, and this is the one file in the release where that rule is easiest to break by habit. |
| T-06-05-05 | Information disclosure | `LICENSES.md` repository URLs | low | accept | Every URL comes from the package's own published manifest and is already public on crates.io. |

Supply chain provenance beyond the licence field, for example checking a package
against a registry signature, is canon and is owned by `/gsd-secure-phase` and by
plan 06-01's blocking package legitimacy checkpoint. It is not minted here.
</threat_model>
