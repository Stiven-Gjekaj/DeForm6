## The two warning shapes, and the fix for each

Measured at plan time by running `cargo doc --no-deps --workspace`. Both shapes
and their idiomatic fix come from `06-PATTERNS.md`.

1. **`public documentation for X links to private item Y`.** The doc comment on a
   public item writes an intra-doc link to a private helper or a private constant.
   Fix: drop the surrounding square brackets and keep the identifier as plain
   code-formatted text inside backticks. This matches the convention the codebase
   already uses when it names a private helper in prose.
2. **`unresolved link to X`.** Three sub-shapes.
   - A link to a `std` item, for example `Display` in
     `crates/deform6/src/vb/ocx.rs`. Fix: fully qualify the path, for example
     `std::fmt::Display`, so rustdoc can resolve it.
   - A link to a test function name from a library doc comment. Rustdoc never
     compiles the test crate under `--no-deps`, so these can never resolve. Fix:
     drop the square brackets, keep the name as code text.
   - A link to an item rustdoc cannot see from that scope, for example
     `SafeName::file_name` or `ComponentTable::walk`. Fix: drop the square
     brackets, or fully qualify the path if the item is public and reachable.

Line numbers move after each fix, so re-run
`cargo doc --no-deps --workspace 2>&1 | grep -B1 -A2 '^warning'` after each file
rather than working from a list captured once.
