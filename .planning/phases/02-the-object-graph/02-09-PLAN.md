Write the pinned file and the test that reads it.

**The shape.** One table per program, keyed by the executable path relative to `corpus/`, quoted because the paths hold spaces and forward slashes. Three values per entry: the count of public procedure names the tool recovered, the count of procedure slots the binary declares, and their ratio rounded to two decimal places. `RESEARCH.md` names the key trap directly: three corpus directories hold more than one compiled program, so a key built from the leaf directory name collides. Use the path.

**The two counts, per D-11 and D-10.** The recovered count is the number of public procedure names the library recovered, which is the same number plan 02-08 matched against the original source in both directions. The declared count is the sum of the procedure slot count the binary declares over every object, including the standard modules, because the standard-module cap is real and stating it is the honest thing rather than removing it from the denominator to make the number look better. The object whose source the repository does not hold is excluded from both counts, because it is excluded from both sides of plan 02-08's comparison and two files must not count different sets.

Take both counts from the function plan 02-08 wrote. Do not recompute them here with a second arithmetic; `AGENTS.md`'s Measurement section requires the number that can be proved, and two arithmetics eventually prove two different numbers.

The measured totals are 185 recovered and 904 declared, with 23 of the declared slots inside standard modules. Thirteen programs recover nothing, which is correct behaviour for a program whose objects are forms carrying only private event handlers. The ratios run from 0.00 to 0.71 across 24 distinct values, so this pin has real variance and can move in both directions.

**No object ratio.** Per D-11 object recovery is not in this file. It is 44 of 44 with no variance and plan 02-08 asserts it as an equality. Write a comment at the top of the file saying so, so nobody adds one later.

**The two failure messages, per D-12.** Compare the integer counts, never the rounded ratio, because a float comparison is fragile and the ratio is a reader's convenience.

- The pinned number is above the measured number. The pin claims the tool recovers more than it does, so something the pin expects is missing. That is `REGRESSION`. Print the program key, the pinned number, the measured number, and the list of public procedures the source declares that the tool did not name. That list is empty today, because the tool names every one of the 185, so when it is empty the message must add one sentence saying that nothing the source declares is unrecovered and that the pin therefore disagrees with a tool that lost nothing. Say the true thing rather than printing an empty list and leaving the reader to guess.
- The pinned number is below the measured number. The tool recovers more than the pin claims. That is `MOVED UP`. Print the exact block of text to paste into the file, formatted the same way the update command writes it, so a copy and paste is enough.

Get the direction right. `ROADMAP.md`'s criterion 3 was corrected to this pairing and the message describes what happened to the **tool**, not to the file. Write both words as constants and write a comment above each giving the reasoning in one sentence, because a reader who reasons from the file instead of from the tool arrives at the opposite pairing.

**The ratio column is load bearing.** Recompute it from the two counts and compare it against the stored value, so a hand-edited ratio that disagrees with its counts fails. Compute it by converting each count into a double precision number with the infallible conversion, dividing, and formatting to two decimal places; compare the formatted text and not the numbers, so the writer and the reader agree by construction.

**Both directions on the key set.** A key naming no program and a program with no key are two different mistakes and get two different messages. Without the first, a stale key from a removed program passes forever; without the second, a newly vendored program is silently unpinned. This is the same both-directions rule plan 02-08 applies to names, applied to keys.

Write `crates/deform6/tests/ratios.rs`, declaring the shared module the same way the other test binaries do, with the path attribute, the allowance and its reason. Read the pinned file from the repository root, at the manifest directory joined with the path up to the workspace root and then `tests/ratios.toml`.

Write the seven behaviours as tests. For the fourth, fifth and sixth, do not edit the file on disk. Parse the committed file, change one number in memory, and run the comparison against that value, so the test proves the message without leaving the tree dirty and without depending on a test that runs before it.

Then break the covered behaviour on purpose, three times. First, swap the two words so a fall prints `MOVED UP`, and confirm the fourth and fifth behaviours both fail. Second, compare the rounded ratios instead of the counts, and confirm a one-count edit no longer fails. Third, drop the check that every corpus program has a key, delete one entry from the parsed copy, and confirm nothing fails; that is the finding, so write the covering test if it is missing and re-break. Restore all three, re-run, and record all three observations in the SUMMARY.
