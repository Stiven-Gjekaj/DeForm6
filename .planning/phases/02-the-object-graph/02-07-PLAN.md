Create `crates/deform6/tests/support/mod.rs` declaring `pub mod rules;` and `pub mod vbp;`, and `crates/deform6/tests/support_selftest.rs` as the test binary that exercises them.

**The shared-module trap comes first, because it is the one that costs a cycle.** A directory under `tests/` is not itself a test target; only a `.rs` file directly under `tests/` is. So `support/` is compiled once into every test binary that declares it, and each binary uses a different subset, which produces an unused-item warning that `-D warnings` turns into an error. Declare it in each binary as

    #[path = "support/mod.rs"]
    #[allow(dead_code, reason = "cargo compiles this shared module into every test binary and each binary uses a different subset")]
    mod support;

and write the reason out, because a bare allowance is what `AGENTS.md` forbids and a reason is what makes it reviewable.

Now write `support/vbp.rs`. Per D-06 it names nothing from the library. No import of the crate under test, no shared type, no shared constant. It reads bytes and text and it answers questions about a project file. Say that at the top of the file in one sentence with the reason: a harness that shares a reader agrees with a bug in that reader.

**Selection.** The entry point takes the path of an executable and gives the project file that declares it. The rule, in three steps:

1. The corpus entry directory is the immediate child of `corpus/vb6-code/` or `corpus/public-domain/` that contains the executable.
2. Collect every project file reachable under that directory, matching the extension case-insensitively.
3. Select the one whose executable name key equals the file name of the executable, compared case-insensitively. Exactly one must match. Zero matches and two matches are both loud failures naming the executable and every candidate.

A script this planner ran proved this rule over all 44 executables: every one resolves to exactly one project file, and 8 of the 44 have more than one candidate inside their entry directory. Those 8 are the two programs under `SK-TFTP-Sample__VB6`, with two candidates each, the three under `machineLanguageConversion`, with three each, and the three under `Brightness-effect`, with four each. So the key is doing real work on 8 files and a test asserts the number, because a selection that never has to choose is a selection that cannot be wrong and cannot be proved right.

**The scope is not decoration.** A corpus-wide index keyed on the executable name key collides in this corpus. `SK-MCI-Sample__VB6/MCI.VBP` and `SK-Gradient-Sample__VB6/Project1.vbp` both declare the executable name `Project1.exe`, and both projects ship a `demo/Project1.exe`. A global index resolves one of the two executables to the wrong project, and the wrong project declares one more object than the right one, so the differential would report a recovery failure that is really a lookup failure. Write the third behaviour as a test that builds the global index and asserts the collision, so the reason for the scope is a fact in the repository and not a sentence in a plan. This is a measurement this planner made; it is not in the roadmap, the context or the research document.

Two shapes make the scope necessary and neither is a same-directory search. `MCI.VBP` is upper case, its executable sits in a `demo/` subdirectory, and the project file name bears no resemblance to the executable name. The two projects under `SK-TFTP-Sample__VB6` are reachable from one shared parent.

**Never iterate project files.** The repository holds 45 of them and 44 executables. `Brightness-effect/Part 3 - DIBs/Brightness3.vbp` declares `dibBrightness.exe`, which the repository does not hold, so a harness that walked project files would test 45 projects and fail on one that has no binary at all. The walk starts from executables. Write the fourth behaviour as a test asserting both counts, 44 and 45, so the day somebody vendors the missing binary the test says so.

**Quoting.** Per D-05, a value runs from the first quote on the line to the last quote on the line. `Sepia.vbp` carries a title with two inner quotes and a reader written to stop at the first inner quote returns a truncated value without failing. Take the first index of a quote and the last index of a quote and everything between them, and return nothing when there are fewer than two.

**Absence.** Per D-05 an absent key is not an empty value. Return an optional and let the caller decide. `SK-Gradient-Sample__VB6/Project1.vbp` has no title key, because the compiler omits it when the title equals the project name, and the fallback is the name key.

**Encoding.** Read every file as bytes and decode each byte as its own code point. Two project files in this corpus carry a copyright sign in a version comment, and a reader that assumed a wide encoding would either lose the line or refuse the file.

Write the seven behaviours in `support_selftest.rs`. Then break the covered behaviour on purpose, three times. First, take the value between the first quote and the next quote, and confirm the `Sepia.vbp` test fails. Second, return an empty string for an absent key, and confirm the absent-title test fails. Third, build the candidate list from a corpus-wide index instead of from the entry directory, and confirm one of the two programs named `Project1.exe` resolves to the wrong project file. Restore all three, re-run, and record all three observed failures in the SUMMARY.

Write `support/rules.rs`. VER-04 requires that what the compiler does not keep is excluded by a written rule, not by a per-program allowance, so the shape of this file is the requirement: rules as data, each with an identifier, a reason and a predicate, and no branch anywhere that names a program.

The five rules:

- **A standard module carries no procedure names.** Type data is part of the dispatch plumbing every user form, class and user control carries and the compiler cannot strip, and a standard module is not such an object. Per D-13 its procedure name array pointer is null outright, in 8 of 8 corpus module objects, so the procedures are name-less through the object table rather than merely prototype-less. Excludes 8 objects and 23 procedure slots across the corpus.
- **Only a public procedure survives by name.** A procedure the source declares private or friend produces a null entry in the name array. The class `pdOpenSaveDialog` in `Grayscale-effect` declares its two procedures friend and recovers no name, which is correct behaviour and not a shortfall.
- **An object the project file does not list was never compiled in.** Two projects hold a common dialog class source on disk that their project file never lists.
- **An object the project file lists whose source the repository does not hold has no source-side expectation.** It is excluded from both sides of the procedure comparison, never from one side only, because dropping it from the expectation while keeping it in the recovery would make the recovered count exceed the declared count. Exactly one object in the corpus, in `Edge-detection`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the harness -> the library under test | The harness must not import the library, or a bug in the library becomes a bug in its own expectation. |
| a corpus path -> a project file selection | A wrong selection silently moves a program's whole expectation to a different project. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-31 | Repudiation | `support/vbp.rs` sharing code with the library | high | mitigate | A grep over the file's non-comment lines counts zero references to the library, run in the acceptance command of every task in this plan and again in plan 02-08. Per D-06 this is the property that makes the differential evidence rather than a round trip. |
| T-02-32 | Spoofing | project file selection by name key alone | high | mitigate | The search is scoped to the corpus entry directory before the key is applied, and a test proves that a corpus-wide index collides on two real projects. Without the scope the harness would compare one program against another program's source. |
| T-02-33 | Repudiation | an exclusion rule that matches nothing | medium | mitigate | A test finds the corpus cases each rule matches and fails when the count is zero, so a rule cannot silently become a blanket allowance. |
| T-02-34 | Repudiation | an exclusion applied to one side only | high | mitigate | The absent-source rule excludes from both sides of the comparison, and a test fails when the recovered count exceeds the declared count, which is what a one-sided exclusion produces. |
| T-02-35 | Denial of service | the harness reading corpus files | low | accept | The harness runs under `cargo test` over a vendored, fixed corpus that this repository controls. It is not exposed to hostile input, unlike the library, so the strict bounds discipline of `crates/deform6/src/` does not apply to it. |
