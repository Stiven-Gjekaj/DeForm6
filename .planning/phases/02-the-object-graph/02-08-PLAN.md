  <action>
Write `crates/deform6/tests/support/source.rs` and declare it from `support/mod.rs`.

`AGENTS.md`'s Measurement section requires the ratio to be measured against the original source the executable was built from, not against what the tool produced. The recovered side is a count of names the library pulled out of the binary; the declared side has to come from the source text. This file is the reader that produces the declared side, and per D-06 it names nothing from the library either.

Match a declaration on its own line: optional leading whitespace, an optional scope keyword, an optional static keyword, then the subroutine, function or property keyword, then the name. Treat a missing scope keyword as public, because that is the default for a procedure in a form or a class. A property getter, setter and letter each count as one entry, so a getter and a letter with the same name give two entries.

Match only the first line of a declaration. A continued argument list wraps with a line continuation and its continuation lines must not match, or a declaration with four wrapped arguments would count five times.

Read the file as bytes and decode each byte as its own code point, the same rule the project file reader uses.

Write the seven behaviours as tests in `support_selftest.rs`, next to the tests plan 02-07 wrote, so the harness proves itself in one place.

The fifth behaviour is the aggregate this plan's task 3 depends on. A script this planner ran over the corpus, applying the standard module rule and the absent-source rule, counted 185 public procedures declared in source and 185 recovered by the library, with the names matching one for one in all 44 programs and zero mismatches in either direction. Assert 185 here so a change in this reader is caught before it moves a comparison.

Then break the covered behaviour on purpose, twice. First, treat a missing scope keyword as private, and confirm the sixth behaviour fails with an empty list for the class whose four procedures carry the public keyword explicitly, and that the 185 total drops. Second, allow a continuation line to match, and confirm the total rises above 185. Restore both, re-run, and record both observed failures in the SUMMARY.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the recovered side -> the declared side | Two independent readers meet only at the comparison. If either borrowed from the other the comparison would agree with a shared bug. |
| an exclusion rule -> what the comparison may drop | A rule applied to one side only turns a real disagreement into a passing run. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-36 | Repudiation | a one-directional assertion | high | mitigate | Both set differences are computed and asserted, and a doctored input proves the subset check passes where the two-directional check fails. This is the exact failure this repository already lived through. |
| T-02-37 | Repudiation | an exclusion applied to one side only | high | mitigate | A test removes the absent-source object from the expectation alone and asserts the recovered total then exceeds the declared total, so a one-sided exclusion fails loudly. |
| T-02-38 | Repudiation | the harness sharing a reader with the library | high | mitigate | A grep over the non-comment lines of both harness readers counts zero references to the library, run in the acceptance command of every task in this plan. |
| T-02-39 | Repudiation | a comparison against the tool's own output | high | mitigate | The declared side is read from the project file and the source text the executable was built from. `AGENTS.md` says a round trip through this project's own writer and parser is not verification, and the module doc comment repeats it. |
| T-02-40 | Denial of service | the harness over a hostile corpus | low | accept | The corpus is vendored and fixed and this repository controls it. The harness is not exposed to hostile input; the library is, and its own bounds discipline is unchanged. |
</threat_model>
