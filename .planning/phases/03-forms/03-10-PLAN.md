## What stays manual after this plan

`03-VALIDATION.md` names two verifications this repository's gate cannot
automate, and both are follow-up work outside phase 3.

1. **The opcode table beyond the safe provenance subset**, about 158 of the
   198 corpus pairs. Per D-01 the table is never committed, so no automated
   test here can assert its contents. A human at a working Visual Basic 6
   install builds the table with the committed derivation tool and runs
   `deform6 inspect --opcode-table <path>`.
2. **Closing one remaining pair** by the method `STRUCTURES.md` section 13
   used to close gap 1: compile a small original program that sets one
   property, and diff the compiled bytes against a blank control.

Every other phase 3 behaviour has automated verification. The
`<human-check>` in this plan's verification block records the two, so they are
answered at the end of the phase rather than assumed.
