<objective>
Build the string reader every property reader in this phase shares, with one
rule that must never be relaxed: the cursor advances by the declared length,
never by what the decoder found.

Purpose: FRM-03 needs property values, and many of them are strings.
`STRUCTURES.md` gap 13 says the string encoding rule in the form property
stream is not known, and that the one public heuristic is unsound by its own
byte accounting. A string read that sets its own pace does not fail loudly. It
shifts the cursor and corrupts every property after it in the same block. That
is the one failure in this phase that cascades.

Output: `crates/deform6/src/vb/vbstr.rs`.
</objective>

    - `VbStr::read` at an offset with a declared length of 0 gives an empty string and a declared end 3 bytes past the start.

    - The declared end is the start plus 2 for the length field, plus the declared length, plus 1 for the trailing null byte.
    - The returned cursor equals the declared end in every successful case and in every refused case alike.
    - A declared length that runs past the end of the enclosing region gives a `Defect` naming the byte offset, the declared length, and the bytes that remain.
    - A declared length whose end overflows a `u32` gives a `Defect` naming the byte offset.
    - An ASCII read maps each byte to its own Latin-1 code point. A byte of 0xA9 gives the character at code point 0xA9.
    - A UTF-16 read consumes the declared length in bytes, not in code units, and pairs the bytes little endian.
    - `VbStr` exposes the decoded text and the declared end. It exposes no other advance.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file to parser | The declared length of every string property comes from the file. It sizes a read and it moves the cursor. |
| property to property | One string property's advance decides where the next property starts. A wrong advance corrupts every property after it in the same block, and does so silently. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Tampering | The cursor advance in `vb/vbstr.rs` | high | mitigate | The cursor is the declared end in every case, including every failure case. `VbStr` exposes no other advance, so a caller cannot take one. A test asserts the advance is the same whatever the 5 declared bytes hold. |
| T-03-27 | Denial of Service | A declared string length used to size a read | high | mitigate | The declared end is checked against the enclosing region before any subregion is taken. No allocation is sized from the declared length before that check. |
| T-03-28 | Tampering | A declared length whose end overflows a `u32` | high | mitigate | Every step uses `Off::checked_add` on a bare `u32`. An overflow gives a `Defect` naming the byte offset rather than a wrapped offset that points back inside the file. |
| T-03-29 | Information Disclosure | A partial string emitted after a failed decode | medium | mitigate | A read that lands under neither encoding gives an empty text and a `Defect`. It never gives the bytes it managed to read, which could be an unrelated property's payload. |
| T-03-30 | Denial of Service | Repeated decode attempts on one property | low | mitigate | The reader tries at most two encodings. There is no loop over encodings and no fall back scan to the next null byte. |
