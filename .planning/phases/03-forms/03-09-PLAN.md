<objective>
Recover the event handler names bound to each control, and say plainly which
part of that answer this repository can give and which part it cannot.

Purpose: FRM-06 needs the event handler names. The file holds the structure:
which control has which event slots, and which slots have a handler. The file
does not hold the event name. The slot index is the event's ordinal in the
control's default source interface, and turning an ordinal into a name needs a
table. `03-CONTEXT.md` D-02 says that table takes the same discipline as the
opcode table: build it from independent public sources with each fact cited,
and never from a type library dump.

Output: `crates/deform6/src/vb/controlinfo.rs`.
</objective>

## Why this module resolves OptionalObjectInfo itself

`dwControlCount` and `lpControls` live in `OptionalObjectInfo`, which sits
immediately after `ObjectInfo` at `Object.lpObjectInfo` plus 0x38.
`STRUCTURES.md` section 5.3 gives the layout. Phase 2 did not read that
structure, because nothing in phase 2 needed it.

This module resolves it independently from `Object::lp_object_info`, which is
already public. It does not extend `ObjectInfo` in
`crates/deform6/src/vb/privateobj.rs`. STATE.md records the same decision from
phase 1: `vb/object.rs` resolves `lpObjectArray` independently rather than
extending `ObjectTableHead`, so one plan keeps sole ownership of one file.
