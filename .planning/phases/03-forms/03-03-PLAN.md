<assumption_delta_decision>
The deterministic detector fired one `pluralization` signal on this phase, on
the phrase "a second independent reader" in the ROADMAP phase section.

**The noun that is now primary:** an independent source reader under
`crates/deform6/tests/support/`. Phase 2 had one, `vbp.rs`, for the `.vbp`
project file. This plan adds a second, `frm.rs`, for the `.frm` form file.
Phase 4 will need a third for `.bas` and `.cls`.

**The decision:** `add-alongside`, for the parse shape. A `.vbp` is a flat key
and value file. A `.frm` is a nested `Begin` and `End` block grammar. They
share no parse code, so there is no general representation to promote. One
reader per source file type is the right model and it stays that way.

**The decision:** `promote`, for the corpus walk. Both readers must walk the
corpus by the same two rules: match the extension with
`eq_ignore_ascii_case`, and read the file as bytes rather than as a string.
Those two rules are the generalisation, and they are the part that is easy to
get wrong once per reader. `03-CONTEXT.md` measured both failures. Task 3
promotes them into one self test that asserts every reader in
`tests/support/` obeys both, so a third reader added in phase 4 cannot quietly
skip a file.

**What would force a later change:** a fourth source file type whose grammar
matches `.frm`'s nested block shape, for example `.ctl` for a UserControl. At
that point the block parser, not the corpus walk, becomes the thing to
promote. The corpus holds zero `.ctl` files today, so that day is not this
phase.
</assumption_delta_decision>
