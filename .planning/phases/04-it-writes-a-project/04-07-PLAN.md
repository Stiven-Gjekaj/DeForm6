<objective>
Put the uncertainty marker where the format allows one, and prove it can reach
nowhere else.

Purpose: a person who opens the recovered project in the IDE should see, at the
top of the code they are about to read, what the tool could not recover. The
report says it in machine readable form. A comment says it where the developer
is already looking.

The whole difficulty is that most of what this phase writes has no legal place
for a comment. A form file's header region accepts six line shapes and none of
them is a comment. The project file has none at all. That leaves one place per
file, and a marker written anywhere else turns a quiet gap into a file the IDE
refuses to load.

Output: one emitter that turns report items into comment lines, one call site
in the one legal place, and tests that prove no comment can appear above the
first attribute line of any written file or anywhere in the project file.
</objective>

  <behavior>
    - The emitter takes a list of report items and a path prefix, and gives back a list of comment lines for the items whose path is under that prefix.
    - Every line begins with an apostrophe at column zero. There is no indented comment and no comment after code on the same line.
    - An item whose confidence is the first word produces no comment. Only the inferred and unrecoverable words produce one.
    - A comment names the path, the basis in plain words, and the byte offset from the item's first evidence record.
    - The block of comments opens with one marker line naming the tool, so a developer reading the file can tell these lines from the developer's own comments and can find them with a search.
    - No comment holds a percentage, a score, or a claim that a statement was recovered.
    - A recovered string inside a basis has every line ending character removed before it reaches a comment line, because a comment runs to the end of the line and a line ending inside one would put the rest of the text into the file as code.
    - Passing an empty item list gives an empty line list and not a marker line on its own.
  </behavior>
  <action>
    Generate every comment from a report item. Do not add a function that takes
    a free string, because a call site with one would write a comment that has
    no matching item, and the promise this plan makes is that a comment in the

    Filter by path prefix. A form file gets the comments for that form and its
    controls. A class file gets the comments for that class. A module file gets
    the comments for that module. The path builder from plan 04-06 already gives
    a prefix a caller can pass.

    basis, and give the byte offset from the evidence. Do not summarise, do not
    count, and do not give a proportion. The project rules bar a percentage and

    Strip line ending characters out of any recovered text before it reaches a
    comment line. A comment runs to the end of the line, so a carriage return or
    a line feed inside a basis would end the comment and the rest of the text
    would be compiled as code. Do the strip in this file, not at the call site.
