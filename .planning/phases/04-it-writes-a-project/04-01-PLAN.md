<objective>
Prove the whole write path on one corpus program before the phase expands to
44, then make the name layer and the model layer complete enough that no
later plan in this phase has to widen them.

Purpose: every layer of this phase is new. Nothing in the crate writes a file
today. A phase that built the model, then the values, then the `.vbp`, then
the `.frm`, then the report, then the command line would discover an
architectural fault after six committed layers. One thin path through all six
finds it after one.

The tracer also settles the question this phase raises about what a recovered
name is. Phases 1 to 3 recovered a name to display it. This phase turns the
same name into a file path. That is the whole of threat T-4-01, and the answer
belongs in the first commit, not in a later hardening pass.

Output: a `write` module set, a `SafeName` type every emitted name passes
through, the Latin-1 and CRLF emitter primitives, a complete `ProjectModel`,
a locked report item shape, an `extract` subcommand that writes a directory,
and a test that takes `Fast_Flames.exe` to files on disk and compares them
against the committed source it was built from.
</objective>

<assumption_delta_decision>
**The noun that is now primary: a sanitized VB6 name.**

Phases 1 to 3 recovered a name for one purpose. A name was a `String` on
`ObjectReport`, `FormReport` or `ControlReport`, and its only consumer printed
it. Phase 4 gives the same recovered name a second purpose: it becomes a file
name on disk, a `Form=` line in the `.vbp`, an `Attribute VB_Name` value, and a
path key in the JSON report. That is a real change in what a recovered name is,
not a change in how many of them there are.

**Decision: `promote`.**

`write/model.rs` defines `SafeName` and it is the single source of every name
this phase emits. `ProjectModel`, `FormModel`, `ControlModel` and `CodeModel`
carry `SafeName` and carry no bare `String` name field beside it. The raw
recovered string is demoted to a detail inside `SafeName`, reachable only
through `SafeName::raw`, and its only consumer is the report's `evidence`.

Rationale: adding a sanitizer alongside a still usable raw name leaves the raw
name reachable, and a writer that reaches past the sanitizer to build a path
is exactly threat T-4-01. A type that carries no reachable raw name makes the
threat a compile error rather than a review finding.

Reversibility: `costly`. Undoing the promotion means touching every writer in
the phase. It breaks no published contract and needs no data migration, so it
is not one way.

Companion invariant, delivered as task 2: a test asserts that `ProjectModel`
exposes no bare `String` name field for an object, a form or a control, and a
second test drives hostile names built inside the test through `SafeName` and
asserts none of them can produce a path separator, a `..` sequence, a NUL byte
or a name longer than 40 bytes.
</assumption_delta_decision>

## Planner assumptions locked in this plan

No `CONTEXT.md` exists for this phase. The four choices below are the
planner's, not the user's. Each one is recorded in the JSON report at the
`/meta` path so a reader of the output sees the choice, and each one is stated
in `04-RESEARCH.md` as an open question the planner was asked to settle.

1. **The `.vbp` file name is `<project name>.vbp`**, taken from
   `Report::project_name` and passed through `SafeName`. The executable does
   not hold the name of its own project file. `project_name` is the one name
   the executable declares for the project, so it is the honest choice.
   Research assumption A4 asked for this to be locked. Reversibility:
   `reversible`.
2. **The JSON report is written to `<dir>/<project name>.report.json`**, the
   same stem, unless `--report <path>` names another place. Reversibility:
   `reversible`.
3. **The short form of the output flag is `-o` and the long form is
   `--output`.** Research assumption A3 left the long spelling open.
   Reversibility: `costly`, because a flag name is a contract for a script
   that calls the tool, but nothing is released yet.
4. **The blob bytes are re read from the original executable bytes at write
   time**, through the range `offset .. offset + 4 + declared_len` that
   `PropertyValue::Blob` already names, rather than widening Phase 3's
   `propstream.rs` to carry them. Research assumption A1 asked the planner to
   pick one. This is why `write::project` takes `data: &[u8]` beside the
   `Report`. Reversibility: `reversible`.
