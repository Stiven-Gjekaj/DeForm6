<objective>
Write the project file the IDE opens: every object, every component, a startup
key that resolves, and a setting block in the order the IDE writes it.

Purpose: this is the file that makes the other four loadable. A form file with
perfect bytes is unreachable if no form line brings it in, and a startup key
that names a form no form line brings in is one of the documented ways to make
the IDE refuse the whole project.

The file is also where the honesty of this phase shows most plainly. A native
executable does not carry its compiler flags, its help file, its version
strings or the identity of its startup form. The writer has to produce a
loadable value for each of them anyway. Every one of those values is a choice,
and every choice becomes a report item that says so.

Output: a project file writer, the component line grammar, the 34 key setting
block in corpus order, and one report item per value the writer chose rather
than recovered.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recovered object name to component line | Every name on a component line came from an untrusted file and names a file on disk that the IDE will then open. |
| recovered component identifier to object line | The identifier and the file name a declared component carries are file derived strings written into a line the loader parses. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-01 | Tampering / Elevation of Privilege | the component lines | high | mitigate | This writer builds no file name. Every name comes from a `SafeName` and every file name from the model's own file name function, which plan 04-01 task 2 proved cannot emit a path separator, a parent directory sequence or a NUL byte. A source assertion in task 1 proves the writer calls the model's function and never assembles a name itself. |
| T-4-05 | Tampering | a recovered value written into a quoted setting | medium | mitigate | A recovered string reaching a quoted setting value is passed through the same escaping the value formatter uses, and a value holding a line break is refused with a report item rather than written, because a raw line break would end the line and the next bytes would parse as a new key. |
| T-4-10 | Denial of Service | a written resource script key naming a file that is not there | medium | mitigate | The key is never written. Task 2 carries a source assertion that the key name cannot appear in the writer at all. |
| T-4-11 | Repudiation | a default written as if it were a recovery | medium | mitigate | Every compiler flag, the startup form and every omitted version string produce a report item of confidence `inferred` whose basis states that the executable does not carry the value.
