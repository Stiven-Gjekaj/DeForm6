<objective>
Build the machine readable surface of this project: one JSON document that
grades every recovered item by confidence, names the bytes it came from, and
lists every defect the run met.

Purpose: everything else this phase writes is a Visual Basic project, and a
Visual Basic project has nowhere to say how sure the tool is. A form file
cannot carry a comment above its first attribute line. A project file has no
comment line at all. The report is the only place doubt can live for most of
what this tool recovers, and the core value of the whole project turns on it:
a person gets back a project and a report that says how much of it is proved
and how much is inferred.

The second reason this file matters: it is the one surface a script reads. The
roadmap's own acceptance criterion pipes it through a query tool. That makes
the field names and the three confidence words a contract, and it makes byte
identical output across two runs a requirement rather than a nicety.

Output: the flat item array, the three confidence words, the evidence record
with a byte offset, the defect array, the stated limits, and a serialiser whose
output does not change between two runs on the same input.
</objective>
