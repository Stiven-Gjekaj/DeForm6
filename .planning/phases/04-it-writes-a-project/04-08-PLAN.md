<objective>
Give the tool its second subcommand, and make the one place where recovered
data becomes a path on disk safe by construction.

Purpose: every other plan in this phase produces bytes in memory. This one
decides where they land. That makes it the whole of the second threat in this
phase: a recovered name, or a symbolic link, or a path that escapes upward, and
suddenly a tool run on a hostile executable writes outside the directory the
user named.

It is also where the phase's promise about a partial run is kept. A run that
refuses half way through and leaves half a project behind is worse than a run
that refuses and leaves nothing, because the half project looks like a whole
one. Building every file in memory first makes the refusal clean.

Output: the extract subcommand with its three flags, a resolved and checked
output directory, a build then write order, the existing exit codes reused, and
command line tests that prove all of it against real corpus programs.
</objective>

## Flagged assumption from the spec-less edge probe

This phase has no `SPEC.md`, so the edge probe ran over the requirement IDs
instead. One of its ten rows landed on the requirement this plan owns and it
could not be classified into a known edge category. It is recorded here rather
than dropped, and it stays open for `/gsd-verify-work`.

- **WRT-01, category `unclassified`.** The probe could name no edge. The
  planner's reading: the open edge behind WRT-01 is what the output directory
  holds when a run refuses part way through. Task 2 answers it by building
  every file in memory before any byte reaches the disk, so a refusal during
  the build leaves the directory untouched and a refusal during the write can
  only happen after every byte is known. This answer is stated, not proved by
  the probe, and it needs review.

The probe's concurrency row for WRT-04 is also answered here rather than in the
plan that owns WRT-04, because the guarantee is a property of the run and not
of the form writer: the tool is a single threaded command line program that
builds the whole project in memory and then writes it, so an interrupted run
leaves either nothing or a set of complete files, and two runs into two
different directories cannot see each other.
