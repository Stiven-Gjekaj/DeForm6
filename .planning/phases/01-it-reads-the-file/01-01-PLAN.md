<objective>
Create the Cargo workspace, pin the toolchain, put the lint wall in place, prove
the wall rejects the five bad shapes, and run the three-command gate in CI.

Purpose: the safety primitives cannot be retrofitted. ROADMAP names this as the
first risk of the phase: a wall added after the parser exists fires on every
line already written, and the cheap fix then is to allow the lint. This plan
puts the wall in before a single byte of parsing code exists.

Output: a workspace with two crates that compiles clean under the full wall, a
committed script that proves the wall works, and a CI job that runs the gate.
</objective>

<task type="auto">
  <name>Task 2: Prove the wall by writing each of the five bad shapes, watching each fail, and then removing them</name>
  <files>scripts/prove-lint-wall.sh</files>
  <read_first>.planning/phases/01-it-reads-the-file/RESEARCH.md sections 2.3, 2.4, 2.5</read_first>
  <action>
ROADMAP success criterion 4 says a deliberate `d[0]`, a deliberate `a + b` on a file-derived value and a deliberate `.unwrap()` each stop the build. Do not assert that. Demonstrate it, and leave behind something that can demonstrate it again.

Write `scripts/prove-lint-wall.sh`, a POSIX shell script with `set -eu`. The script writes a probe source file, runs clippy, checks that each expected lint fired, and removes the probe.

Put the probe at `crates/deform6/examples/lint_wall_probe.rs`. An example target is the right vehicle for three reasons: `cargo clippy --all-targets` compiles `crates/*/examples/*.rs` under the full wall, which RESEARCH.md section 2.5 measured directly; an example is discovered by its path, so the script does not have to edit a `mod` line; and the probe therefore never becomes part of the library. Install a shell `trap` on EXIT that removes the probe file, so a failing run does not leave a broken tree behind.

The probe body holds the eight shapes from the table in RESEARCH.md section 2.3, each on its own line inside one function that takes a byte slice and two integers: an index of a slice with square brackets, a range slice of the same value with square brackets, an addition of two integers with the plus operator, a call to `unwrap` on an `Option`, a cast from `u64` to `u32`, a cast from `i32` to `u32`, an integer division, and an `unsafe` block.

The script then runs `cargo clippy --all-targets --message-format short 2>&1` and captures the output without letting a non-zero exit status stop it. It asserts that the output names every one of these seven lints or messages: `clippy::indexing_slicing` for the index, `clippy::indexing_slicing` for the slice, `clippy::arithmetic_side_effects` for the addition, `clippy::unwrap_used`, `clippy::cast_possible_truncation`, `clippy::cast_sign_loss`, `clippy::integer_division`, and the rustc message for an `unsafe` block, which is requested on the command line as `-F unsafe-code` because the workspace table sets `unsafe_code = "forbid"`. Print one PASS line per shape with the lint that caught it, and exit 1 naming any shape whose lint did not fire.

Do not add `x as usize` where `x` is a `u32` to the expected list. RESEARCH.md section 2.4 measured that this cast compiles clean, because `usize` is at least 32 bits on every target clippy models by default. Only the reverse direction fires. A probe that expected it would fail for the wrong reason.

After the script removes the probe, it re-runs the three gate commands and requires all three to be green, so the script proves both that the wall fires and that the tree it leaves behind is clean.

Run the script once by hand as part of this task. Read its output. Confirm every shape is caught by the lint the table names, then confirm the tree is clean. Record the observed output in the SUMMARY. If a shape is not caught, the wall is wrong, not the probe: fix the `[workspace.lints]` table.
