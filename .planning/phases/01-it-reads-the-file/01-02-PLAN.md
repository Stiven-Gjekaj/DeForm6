<objective>
Build `read/region.rs`: the `Region` bounded window and the `Off`, `Rva` and
`Va` newtypes. Zero dependencies. Every read returns a fallible value.

Purpose: ROADMAP names the overflow trap as a correctness fault, not a crash.
In a release build `off + len` wraps silently, the wrapped sum is small, the
small sum is in bounds, and the parser reports real bytes from the wrong place
with confidence. This file is what makes `checked_add` the only shape that
compiles, and it is what every later parser in the project reads bytes through.

Output: one file with no dependency, and a committed script that proves the
type refuses the three shapes a caller must not be able to write.
</objective>

  <name>Task 1: The three offset newtypes, with no Add and one checked bridge between the spaces</name>
  <files>crates/deform6/src/read/region.rs</files>
  <read_first>.planning/phases/01-it-reads-the-file/RESEARCH.md sections 3.1, 3.4</read_first>
  <behavior>
    - `Off::new(0x10).checked_add(4)` is `Some(Off::new(0x14))`.
    - `Off::new(u32::MAX).checked_add(1)` is `None`.
    - `Off::new(4).checked_sub(8)` is `None`.
    - `Va::new(0x401760).to_rva(0x400000)` is `Some(Rva::new(0x1760))`.
    - `Va::new(0x1000).to_rva(0x400000)` is `None`, because the address is below the image base.
    - `Va::new(0).is_null()` is true.
    - `Rva::new(u32::MAX).checked_add(1)` is `None`.
  </behavior>
  <action>
Write the three newtypes into `read/region.rs` with the exact public signatures RESEARCH.md section 3.1 lists. That list was compiled clean under the full wall on 1.97.1. Do not add a method the list does not name, and do not widen a signature.

The derive set on all three is `Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Debug, Hash`. Per D-10 there is no `Add`, no `Sub`, no `From<u32>` and no `Deref` on any of them.

`Off` carries `new`, `get`, `checked_add`, `checked_sub`, and a private `index` method that returns `usize`. `Rva` carries `new`, `get`, `checked_add`. `Va` carries `new`, `get`, `is_null`, `to_rva`.

Every `checked_add` takes a bare `u32` on the right-hand side, never another newtype. Adding two offsets is meaningless and the signature must refuse it. A length is a `u32`. This is the whole point: `off.checked_add(len)` compiles, `off + other_off` does not exist, and `off.get() + len` is stopped by `clippy::arithmetic_side_effects`.

Write the `checked_add` bodies as `const fn` using a `match` on the primitive `checked_add`, not `.map(Self)`. `Option::map` is not a `const fn` on 1.97.1, which RESEARCH.md section 3.4 measured. Keep the `const`, because it lets a table of fixed offsets be built at compile time in a later phase.

`Va::to_rva` is the only bridge between the three integer spaces and it is a `checked_sub` against the image base. A virtual address below the image base returns `None`, never a huge wrapped address that lands back inside the file.

`Off::index` uses `usize::try_from(self.0).unwrap_or(usize::MAX)`. Not an `as` cast. RESEARCH.md section 2.4 measured that `x as usize` where `x` is a `u32` compiles clean under the wall, so the wall would not catch a wrong cast there; the `try_from` form is written so no reader has to work out which direction is safe. `unwrap_or` is not `unwrap`, so `clippy::unwrap_used` does not fire. The saturating fallback is correct: a `usize::MAX` index fails the `get` that follows it.

Put `#[must_use]` on every accessor.

Write the seven behaviours above as a `#[cfg(test)]` module in the same file. Per RESEARCH.md section 2.5 the module carries an outer `#[allow(clippy::unwrap_used, clippy::indexing_slicing, reason = "...")]` attribute, and it uses `#[allow]`, never `#[expect]`: an unfulfilled expectation is itself a build error, so a test module that stops using `unwrap` would break the build for the wrong reason.

Then break the covered behaviour on purpose. Replace the `checked_add` body with a `wrapping_add` that always returns `Some`, run `cargo test -p deform6 --lib`, and confirm the `Off::new(u32::MAX).checked_add(1)` test fails. Do the same for `to_rva`: replace the `checked_sub` with a `wrapping_sub` and confirm the below-image-base test fails. Restore both, re-run, and record both observed failures in the SUMMARY. A test that cannot fail is worse than no test.
  </action>
  <verify>
    <automated>cargo test -p deform6 --lib && cargo fmt --all --check && cargo clippy --all-targets -- -D warnings</automated>
  </verify>
  <done>

<task type="auto" tdd="true">
  <name>Task 2: The Region bounded window, with no infallible accessor</name>
  <files>crates/deform6/src/read/region.rs</files>
  <read_first>.planning/phases/01-it-reads-the-file/RESEARCH.md sections 3.1, 3.2, 3.3, 3.5</read_first>
  <behavior>
    - A `Region` over eight bytes returns `Some` for `u32_le` at offset 4 and `None` at offset 5.
    - `take` at an offset whose length runs one byte past the end returns `None`.
    - `take` with a length that overflows a `u32` when added to the offset returns `None`, not a short read.
    - `u16_le`, `u32_le`, `i16_le` and `i32_le` decode little-endian and agree with the bytes written into the test buffer.
    - `cstr` returns the bytes before the NUL, and returns `None` when no NUL appears inside `max`.
    - `subregion` rebases: a subregion taken at offset 0x10 of a region based at 0x1760 reports `file_offset(Off::new(0))` as `Some(Off::new(0x1770))`.
    - `off_le` and `va_le` return the typed newtype, not a bare `u32`.
    - `len` on a region over an empty slice is 0 and `is_empty` is true.
  </behavior>
  <action>
Add `Region<'a>` to `read/region.rs` with the exact public signature list from RESEARCH.md section 3.1.

The struct holds two private fields and exposes neither: `bytes: &'a [u8]` and `base: Off`. Per D-10 there is no `as_bytes`, no `as_slice`, no `Deref<Target = [u8]>` and no `Index`. `take` is the only route out, it takes a length, and it returns `Option`. That is the no-infallible-accessor property, and it must be a property of the type rather than a convention.

Every accessor returns `Option`, never `Result`. RESEARCH.md section 3.2 gives the reason and it is worth repeating in a doc comment: the `Region` layer does not know the name of the structure being read or the name of the field, so it cannot build a `Site`, and a `Region` that returned a half-populated `Defect` would be worse than one that returned `None`. The caller turns the `None` into a `Defect` at the site that has the names.

`file_offset` converts a window-relative offset into the absolute file offset that plan 01-03's `Site` requires, and it does that with `checked_add`, so it too returns `Option`. `subregion` recomputes `base` from `file_offset`, so a defect three levels down still names an absolute file offset.

The fixed-width readers are written as `take` followed by `try_into` on the fixed-size array followed by `from_le_bytes`. `try_into` on a slice of the wrong length gives `Err`, and `.ok()?` turns that into `None`. No panic and no `unwrap`.

`cstr` takes a mandatory `max`. It is not a convenience: a file with no NUL byte after the offset would otherwise scan the whole window. Returning `None` when no NUL appears inside `max` is a refusal, not a truncation.

`len` uses `u32::try_from(self.bytes.len()).unwrap_or(u32::MAX)`. Neither cast uses `as`. The saturating fallback over-reports a file larger than 4 GiB, which then fails every bounds check that uses it. That failure is a refusal, not a read.

Put `#[must_use]` on every reader.

Do not decode a string in this file. `char::from(byte)` Latin-1 decoding belongs to the caller in plans 01-05 and 01-07, and the full Windows-1252 table arrives with `VbStr` in Phase 3. Never use `String::from_utf8_lossy` on a VB header string: a byte in 0x80 to 0xFF becomes U+FFFD and the name is lost.

Write the eight behaviours above as tests in the same `#[cfg(test)]` module, building every buffer inside the test from a literal. Do not read a corpus file here: this file has zero dependencies and its tests should have none either.

Then break the covered behaviour on purpose. Change `take` so it checks only the start offset and not the end, run `cargo test -p deform6 --lib`, and confirm the one-byte-past-the-end test fails. Change `subregion` so it keeps the parent's `base` instead of recomputing it, and confirm the rebasing test fails. Restore both, re-run, and record both observed failures in the SUMMARY.
  </action>
  <verify>
    <automated>cargo test -p deform6 --lib && cargo fmt --all --check && cargo clippy --all-targets -- -D warnings</automated>
  </verify>
  <done>
All eight behaviours pass. The two deliberate breakages were run and each made the matching test fail, and both are recorded in the SUMMARY. `read/region.rs` names no crate outside the standard library. The gate is green.

<task type="auto">
  <name>Task 3: Prove the three shapes a caller must not be able to write do not compile</name>
  <files>scripts/prove-region-wall.sh</files>
  <read_first>.planning/phases/01-it-reads-the-file/RESEARCH.md sections 3.1, 3.4; scripts/prove-lint-wall.sh</read_first>
  <action>
The lint wall from plan 01-01 catches a bad shape written with primitives. It does not catch a caller reaching into a `Region` or adding two offsets, because those shapes are refused by the type rather than by a lint. ROADMAP's first named risk is that the safety primitives cannot be retrofitted, and the only way to show a type refuses a shape is to write the shape and watch the compiler reject it.

Write `scripts/prove-region-wall.sh`, a POSIX shell script with `set -eu`, modelled on `scripts/prove-lint-wall.sh`. It writes one probe file per shape, compiles it, requires the compile to fail with the expected rustc error code, and removes the probe. Install a shell `trap` on EXIT that removes every probe, so a failing run leaves no broken tree.

Put each probe at `crates/deform6/examples/region_probe.rs`, one at a time, for the same three reasons the lint wall script uses an example: `cargo clippy --all-targets` and `cargo build --examples` both compile it, it is discovered by its path so no `mod` line has to be edited, and it never becomes part of the library.

Three probes, three expected rustc errors:

First, reaching the bytes of a `Region` directly. The probe constructs a `Region` and names its private `bytes` field. Expect error code E0616, a private field.

Second, adding two `Off` values with the plus operator. Expect error code E0369, no implementation of `Add`.

Third, indexing a `Region` with square brackets. Expect error code E0608, a type that cannot be indexed.

The script runs `cargo build --examples --message-format short 2>&1` for each probe, captures the output without letting the non-zero exit status stop the script, and requires the expected error code to appear. Print one PASS line per shape naming the shape and the error code. Exit 1 naming any shape that compiled, because a shape that compiles is a hole in the type.

If an expected error code differs on this toolchain, record the code the compiler actually produced and use that. The property being proved is that the shape does not compile, not that a particular number appears; but pin whichever code the compiler gives, so a later change that turns a hard error into a warning is caught.

After the last probe, the script removes it and re-runs the three gate commands, requiring all three green.

Run the script by hand as part of this task. Read its output. Record the three observed error codes in the SUMMARY.
  </action>

  </verify>
  <done>
